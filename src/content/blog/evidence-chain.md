跑通一个 GIS Agent 之后，最容易被忽略的问题是：**你怎么证明它给出的结论是对的？**

模型可以生成一段看起来非常专业的解释，解释它筛出了哪些地块、依据是什么。但这段解释的可信度和它背后的栅格文件是否对齐、CRS 是否一致、数据是否覆盖了目标区域，没有必然关系。

这也是 Agent 和传统 GIS 软件最大的差别：传统软件里，分析师是知道自己在操作什么的；Agent 里，如果不给它证据能力，它就是在编。

## 让数据先自己声明能力

我的做法是在工具链最前面加一道**数据健康报告**：系统主动扫描已挂载的数据源，然后明确声明「这份数据能支持什么操作、不能支持什么操作」。

```text
数据源：dem_wuhan
  可读性        ✓
  CRS           EPSG:4490
  覆盖范围      ✓ 覆盖目标行政区
  像元尺寸      10m × 10m
  几何质量      ✓ 无自相交

可支持：坡度计算、高程统计
不可支持：与土地利用栅格的联合分析（网格未对齐，见下）
```

这份声明有两个作用：

1. Agent 在生成计划时就知道哪些工具**当下**可用，而不是等执行到一半才失败；
2. 不可用时，给出的是「为什么不可用」，而不是一个 stack trace。

## 预检要检查什么

数据质量预检我关注这几项：

- **可读性** —— 文件是否真的能打开，能不能只读挂载，有没有依赖被误设成可写；
- **CRS** —— 源数据的坐标参考系。不同 CRS 下的「距离」和「面积」不是一回事；
- **覆盖关系** —— 数据覆盖的空间范围是否包含本次查询的范围；
- **几何质量** —— 自相交、非法多边形、重复点这些问题会直接让空间运算出错。

这四项里，CRS 问题和覆盖问题是最常见的，也是最容易被忽略的 —— 因为文件能打开、查询能返回结果，只是结果是错的。

## 像元安全门控：宁可解释性阻止

有一类问题特别值得单独说：**栅格联合分析的对齐问题**。

DEM 是 10 米分辨率、土地利用是 30 米分辨率，做「坡度 > 15% 且土地利用为林地」这种联合筛选，就必须先确认两个栅格在同一个网格上。如果只是「文件都覆盖这块地」，那是不够的 —— 覆盖不等于对齐。

我的处理方式是设一道**像元安全门控**：联合分析要求明确的网格对齐证据（分辨率、原点、行列数、CRS 全部一致），证据不足时在工具执行前就阻止，并解释清楚差在哪：

```text
✗ 联合分析已被阻止：栅格网格未对齐
  DEM          EPSG:4490  10m  原点 (x0, y0)  行×列 = 4000 × 4000
  土地利用      EPSG:4490  30m  原点 (x0, y0)  行×列 = 1333 × 1333
  → 分辨率不一致，需要先重采样到统一网格
```

这种「阻止」比给一个错的结果要好得多。用户会知道下一步该做什么，而不是拿到一份看起来专业的错误分析。

## 结果要带来源：provenance

任何一条结论，都应该能回溯到它的来源。

在 Spatial Agent 里，每次工具执行都会记录：输入数据集、参数、schema 版本、结果摘要，以及这些结果之间的 lineage 关系。最终输出的每个结论都能顺着这条链往回走。

```json
{
  "conclusion": "候选地块 3 处",
  "provenance": {
    "steps": [
      { "tool": "dem.slope", "version": "1.2.0", "input": "dem_wuhan" },
      { "tool": "landuse.reclassify", "version": "1.0.3", "input": "landuse_wuhan" },
      { "tool": "raster.join", "version": "2.0.1", "grid_alignment": "verified" }
    ],
    "binding_evidence": "raster.join 记录了网格一致性校验通过"
  }
}
```

有了这层，同一个结论在半年后仍然可以被复算。数据换了、代码改了，都能知道结果当时是怎么来的。

## 提前失败比事后解释便宜

这些机制有一个共同点：**它们都把失败往前推**。

预检在生成计划前做，门控在工具执行前做，证据在结果返回时就绑定好。越早失败，诊断的成本越低，错误的传播范围也越小。

反过来说，如果一个 GIS Agent 的结论不能被追问、错误只能在最后一步暴露、失败时只给一句「执行失败」，那它基本不可用于任何严肃的决策 —— 哪怕它演示的时候看起来很聪明。

## 一个必要的免责声明

需要特别说明的是：这类工具产出的是**演示筛选结果**，不代表法定的建设适宜性、规划许可、生态红线或其他行政结论。工具能回答「按这份数据，这些地块满足这些几何条件」，但不能回答「这块地能不能建」。

把这条边界写在系统里，比只写在文档里重要 —— 它会直接进入模型的上下文，影响它怎么表述结论。
